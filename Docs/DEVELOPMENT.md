# 개발 기록

## 2026-10-06 — 초기 구성

사용자 확정: Unity 새 프로젝트, GitHub 새 공개 저장소. 가상 OS 중심 탐색이며 주변 책상과 모니터가 보인다. 엔딩이나 자기소개서식 순서는 없다.

임시 구현 선택: Unity 6000.6.0f1, UI Toolkit, 도형으로 만든 책상과 모니터, 단일 파일 창. 이름은 PR GAME / 저장소 이름은 pr-game. 실제 개인정보와 링크를 임의로 만들지 않는다.

초기 범위: 바탕화면 폴더 4개, 소개 내용 열기와 닫기, 스크롤, 화면 크기에 따른 배치. 현재 미구현: 파일 계층 탐색, 창 이동, 퍼즐, 발견 상태 저장, 음악 재생, 프로젝트 실행 링크.

## 다음 작업

1. 현재 3D 방의 둘러보기와 컴퓨터 전환 감각 검수.
2. 브라우저 기록과 파일을 통해 취향을 알아가는 단서 구성. 직접적인 소개 목록은 넣지 않는다.
3. 사용자와 게임 진행을 정한 뒤 퍼즐·발견 상태·프로젝트 링크를 연결한다.
4. 배포 기기에 맞춰 렌더링 성능과 입력 감각을 검수한다.

## 검증

Unity 새 프로젝트 생성, 초기 씬 생성과 스크립트 컴파일 성공. 배치 실행에서 `PR_GAME_SETUP_OK` 및 정상 종료를 확인했다. 실제 화면과 마우스 조작은 별도 확인이 필요하다.

## 2026-10-06 — 3D 전환 및 VARCO 소품

사용자 확정: 평면 UI 배경 대신 실제 3D 작업실. Start Survey? 구도를 참고하며, 이후 공포 요소를 가볍게 넣는 방향도 논의했다. 자유 탐색과 엔딩 없음은 유지한다.

구현: 3D 방·책상·소품, 모니터 RenderTexture에 UI Toolkit 바탕화면 표시, 실제 스크린 MeshCollider 좌표로 클릭 입력 변환. 우클릭을 누르면 둘러보기, F 집중, Home/Esc 정면, H 분위기 효과 토글. 분위기 효과는 43초 주기의 느린 책상 조명 밝기 변화로 한정했다.

별도 검증 프로젝트에서 컴파일, 모니터 중앙 좌표, 화면 밖 입력 거부, 네 폴더의 포인터 눌림/해제와 닫기, 실제 3D 렌더 캡처를 검사했다. Unity 검색 인덱스 초기화에서 엔진 측 예외가 있었으나 게임 검증은 통과했다. 수동 플레이 감각과 다른 해상도는 후속 확인 대상이다.

VARCO 요청: BenQ ZOWIE XL2540X+, archon M3 600 MINI 블랙, ATK Phantom 블루를 참고한 모델. [제작 기록](../ArtSource/Varco/README.md)에 출처·프롬프트·노드·설정을 기록한다.

첫 VARCO 결과: 제작용 이미지 3개는 성공. 텍스처 포함 3D 3회와 모니터 형상만 생성한 첫 재시도 1회는 모두 실패했다. 이후 사용자 요청으로 다시 실행했다.

## 2026-10-06 — 장비 형태 정리

두 번째 VARCO 생성은 모두 성공했으나, 사용자 검토에서 키보드의 찢어진 면과 마우스의 자동차 같은 잘못된 형상이 지적됐다. 사용자는 반듯한 외곽선과 금속 표현, 마우스의 겹치는 육각형 선 패턴, 중앙 세로 타공, 휠 뒤 잠자리 무늬, 휠 뒤 버튼 없음을 요청했다.

Blender로 직접 구성한 대체 모델도 시험했지만 사용자가 너무 단순하다고 판단했다. 해당 실험은 `Builds/RejectedHardSurface`로 옮기고 실제 프로젝트 씬에는 적용하지 않았다. 사용자는 마우스와 키보드 모두 VARCO 3D를 사용하며, 조금 낮은 폴리곤 수라도 실제 제품의 형태를 최대한 닮게 만들기를 원한다.

후속 입력: 마우스는 ATK 공식 Verge Blue 사선 사진을 변형 없이 직접 사용한다. 키보드는 블랙 제품의 전체 배열과 실제 키캡 확대 사진을 함께 참고한다. 생성 성공만으로 채택하지 않고 형상·패턴·불필요한 버튼 유무를 확인한다.

## 2026-10-06 — Blender MCP 연결과 사진 기반 재구성

이후 사용자 요청으로 Blender MCP 방식으로 전환했다. `mcp-for-blender` 2.1.8과 Blender 5.2 애드온을 설치하고, Codex에 `blender` 서버를 등록했다. localhost:9876의 실제 Blender에 MCP `get_scene_info`와 `execute_blender_code`를 호출해 모델을 만들었다. 애드온 사용 정보 전송 동의와 서버 telemetry는 껐다. 이 단계에서는 VARCO 유료 생성을 추가 실행하지 않았다.

원본과 재생성 스크립트는 `ArtSource/Blender`, Unity FBX와 재질은 `Assets/Art/ReferenceProps`, 배치 프리팹은 `Assets/Prefabs/Refined*.prefab`에 있다. `Desktop3D.unity`에 반영했으며, 재배치는 Unity 메뉴 `PR Game/Apply reference desk props`를 사용한다. 이 메뉴는 현재 열린 씬 대신 저장된 Desktop3D 씬을 열어 수정하므로 먼저 편집 내용을 저장한다.

- 마우스: [ATK 제품 사진](https://www.atk.store/products/atk-blazing-sky-phantom-hollow-carbon-fiber-composite-wireless-gaming-mouse)의 타공 윤곽을 바탕으로 86개 개구부를 배치했다. 평면 제약 삼각분할 후 곡면에 투영하고 두께를 부여해, 3D Boolean에서 나타난 찢어짐을 제거했다. 겹치는 육각형 형태, 중앙 세로 리브, 잠자리 선무늬, 휠과 왼쪽 버튼 2개를 구현했으며 휠 뒤 버튼은 없다.
- 키보드: [archon M3 600 MINI 제품](https://www.preflow.co.kr/product/detail.html?product_no=10776)의 블랙 67키 배열, 한영 각인, 4개 표시등, 행별 높이와 오목한 키캡을 구성했다. 각인을 실제 키캡 표면에 투영해 가려지는 글자를 보정했다. 사용자가 요청한 금속 느낌은 케이스 가장자리의 재질 표현에 반영했다.
- 모니터: XL2540X+ 참고 이미지의 직선 베젤, 낮은 받침대, 원통형 기둥과 빨간 포인트를 구성했다. 화면은 기존 RenderTexture와 클릭 좌표 변환을 유지한다.

검증: Blender 원본의 좌표 유효성, 키캡 67개, 마우스 셸의 비다양체 경계 0개를 확인했다. 수치는 `ArtSource/Blender/validation.json`에 기록했다. 별도 Unity 프로젝트에서 컴파일, 실제 씬 렌더, 모니터 중앙 좌표, 화면 밖 입력 거부, 네 폴더 열기·닫기를 통과했다. Unity 검색 인덱스 초기화 예외는 남아 있으나 게임 검사 완료 마커와 정상 종료를 확인했다.

사진을 바탕으로 재구성한 게임 소품이며 실측 CAD 복제본은 아니다. 마우스 측면의 복잡한 인쇄 그래픽과 내부 기판, 모니터 뒷면 세부 형상은 단순화했다. 고해상도 검토용으로 마우스 약 10.5만, 키보드 약 4.3만, 모니터 약 0.9만 삼각형이며 전용 저사양 LOD는 아직 없다. `ArtSource/Blender/Models`에 개별 렌더와 Unity 배치 화면을 함께 저장했다.

### 곡면 품질 재작업

사용자가 각지고 일그러진 인상을 지적해 형상을 재작업했다. 키캡의 동심 사각 링은 긴 변 중간에서 오목한 곡면을 제대로 표현하지 못해 별 모양 음영을 만들었다. 이를 모서리가 둥근 규칙적인 표면 격자로 교체하고 각인을 새 표면에 다시 투영했다.

마우스는 구간별 직선 외곽을 형태 보존 3차 곡선으로 교체하고, 타공 윤곽의 작은 모서리를 라운딩했다. 뒤쪽이 눌려 보이던 높이 분포도 연속적인 둥근 단면으로 바꿨다. 타공 테두리에서 겹치는 면을 만들던 베벨/두께 처리는 명시적인 셸 연결로 대체했으며, 열린 경계가 있으면 내보내기 전에 중단한다. 휠은 막대 조합에서 미세한 돌기를 가진 둥근 고무 배럴로 바꾸고 새 본체 높이에 맞춰 배치했다. 선무늬는 실제 본체 표면에 투영해 겹침을 줄였다.

기존 기록의 삼각형 수보다 `ArtSource/Blender/validation.json`의 최신 수치가 우선한다. 개별 렌더는 이전과 동일한 카메라 구도이며, `mouse-form-check.png`는 타공 없이 본체 곡면을 확인하기 위한 별도 렌더다.

### 2026-10-07 승인된 OS 시안의 Unity 구현

`PortfolioDesktop`을 UI Toolkit 기반 OS로 교체했다. 시작 메뉴의 사용자명 조건희, 상단 아일랜드, 파일 탐색기와 미리보기, 탭 브라우저·방문 기록·북마크, 편집 가능한 메모, 두 테마, 잠금 화면, 우클릭 메뉴, 개별 삭제 가능한 알림, 통합 검색을 연결했다. 창은 자유 이동·8방향 크기 조절·최소화·최대화/복원·좌우 정렬을 지원한다. 최대화하면 아일랜드가 숨고 손잡이 클릭 또는 드래그로 다시 표시한다. 현재 앱을 잠그고 풀어도 창을 유지한다.

`DesktopFileSystem`이 모든 앱의 공통 파일 목록이다. 사용자 파일의 생성·이름 변경·복사·이동·휴지통·복원이 탐색기, 바탕화면과 검색에 반영된다. 검색은 파일 이름을 기준으로 한다. 메모 자동 저장 외에 **파일로 저장 / Ctrl+Shift+S**에서 이름과 폴더를 지정해 `.txt`를 저장한다. 같은 이름의 다른 파일을 덮어쓰지 않고 오류를 표시한다. 저장 데이터는 OS 전용 JSON이며 실제 PC 문서 파일에 접근하지 않는다. 파일과 내용, 테마, 방문 기록, 북마크, 방해 금지를 저장한다. 창 배치는 잠금 중에는 유지하지만 게임을 종료하면 초기 배치로 돌아온다.

모니터 화면의 기존 좌표가 수정된 FBX와 맞지 않아 화면이 위로 튀어나왔다. `MonitorSurface.FitToDisplay`가 실제 `Screen glass`의 경계에 16:9 화면을 맞추고 작은 안쪽 여백을 유지한다. 편집기와 실행 시 모두 정렬하며, 모델을 바꾼 후에는 `PR Game > Fit OS screen to monitor`를 사용할 수 있다. 드래그 중 화면 밖으로 나갈 때만 화면 평면에 좌표를 연장하고 새 클릭은 실제 화면의 MeshCollider를 맞힌 경우에만 받는다. 모니터 우클릭과 주변 둘러보기, 메모 입력과 F/H/Home 단축키의 충돌을 분리했다.

브라우저는 Chromium/Whale 구도를 구현한 게임 내부 페이지 탐색기이며 외부 인터넷 엔진은 포함하지 않는다. 취향·검색 기록 퍼즐·스토리 진행은 후속 단계다. 일반 예시 파일만 포함한다.

검증은 열려 있는 작업 프로젝트를 종료하지 않고 `Builds/VerificationProject` 복사본에서 `PrGame.Editor.DesktopSetup.PrepareAndVerify`로 실행한다. `DesktopVerification`은 별도 저장 폴더를 사용한다. 저장/백업 복구, 한국어 내용, 생성/검색/이름 변경/휴지통/복원/복사, 화면 경계와 5지점 좌표, 화면 밖 입력 거부, UI 버튼, 창 최대화/원래 크기로 복원/크기 조절, 아일랜드 손잡이, 테마, 알림 개별 삭제, 잠금 복원, 다른 이름과 폴더로 저장 및 다시 읽기를 검사한다. 결과는 `Logs/OSQA/results.txt`, 실제 렌더는 같은 폴더의 PNG다. Unity Editor 검색 인덱스 초기화에서 기존 `ArgumentOutOfRangeException`이 발생하지만 OS 검사 완료와 프로세스 정상 종료를 확인했다.

시각 자원: Lucide PNG 아이콘과 ISC 라이선스, Noto Sans KR와 OFL 라이선스를 포함한다. 원본 가변 폰트의 기본 굵기가 100이라 Unity에서 너무 가늘게 보여 `ArtSource/Desktop/create_regular_font.py`로 400 굵기 TTF를 생성했다. USS의 그림자·흐림은 Unity 6000.6의 UI Toolkit 필터를 사용한다.

### 2026-10-08 방 배치와 컴퓨터 조작 시점

사용자 평면도를 4.4 × 3.8m 방에 적용했다. +Z가 책상 방향이다. 냉장고는 북서쪽, 책상은 북쪽 중앙, 옷장은 북동쪽, 창문은 동쪽 벽, 침대는 남동쪽에 가로 방향, 출입문은 남서쪽 벽이다. 침대 옆에는 옷걸이, 책상 앞에는 T50 참고 의자가 있다. 창문은 책상 정면이 아니라 오른쪽 벽에 실제 개구부로 배치한다.

`SeatedView`는 방 보기와 컴퓨터 조작을 전환한다. 시작은 방 보기다. 우클릭을 누른 채 360도 둘러보고, 모니터 클릭/F로 카메라 위치·각도·화각을 부드럽게 옮긴다. 클로즈업 크기는 실제 모니터 베젤과 가림막의 경계로 계산하며 화면의 제한되는 방향 약 80%에 맞춘다. Esc로 이전 앉은 위치와 둘러보던 방향으로 돌아온다. 보행 컨트롤러는 포함하지 않는다.

접근 클릭과 이동 중 입력은 OS에 전달하지 않는다. 방 보기로 나가면 텍스트 포커스와 드래그 캡처를 해제하고 메모를 저장한다. 창과 파일은 보존한다. 컴퓨터를 조작할 때 우클릭은 OS 메뉴로 남는다. 텍스트 입력 중 F/H/Home으로 카메라가 움직이지 않는다.

`NightRoomBuilder.BakeAndVerify`는 방을 배치하고 조명을 구운 뒤 기존 OS 검사를 실행한다. 목재/벽/천 재질에는 Poly Haven CC0 텍스처를 사용한다. 천은 격자무늬 알베도 대신 단색과 직조 노멀·거칠기를 적용한다. 작은 케이블·손잡이는 라이트 프로브를 사용해 0면적 라이트맵 경고를 방지한다. 실시간 조명과 간접광, 반사 프로브, 접촉 음영을 함께 사용한다.

`RoomViewVerification`은 방 랜드마크/오른쪽 창문, 접근 전후 입력 차단, 16:9·4:3·21:9·9:16의 80% 외곽 프레이밍, 원래 위치 복귀, 입력 포커스 해제와 메모 창 보존을 확인한다. 실제 Unity 렌더를 `Logs/OSQA`에 저장한다. 위에서 본 이미지는 배치 검수용으로 천장만 숨긴 화면이다.

최종 원본 프로젝트에서도 전체 검사를 통과했다. 방 조명 보정이 OS 글자까지 밝게 만들어 대비를 떨어뜨리는 현상을 발견해, 후처리에서 실제 모니터 평면과 깊이를 검사하고 화면 영역의 원래 색을 유지하도록 수정했다. 가림막 등 앞쪽 물체에는 방의 조명 보정을 계속 적용한다. 보정 전후의 모니터 내부 880 × 490픽셀 비교에서 RGB 차이 0을 확인했다. 캡처용 카메라의 화면 비율도 출력 이미지에 맞추어 가로로 늘어나는 검수 이미지 문제를 수정했다.

### 2026-10-08 모니터 조작 화면 점유율 수정

사용자 검수에 따라 모니터 외곽 80% 기준을 폐기하고 OS 표시 영역 자체를 기준으로 확대했다. `screenViewportFraction=0.92`로 16:9 화면에서 가로·세로 각각 92%, 전체 면적 84.64%를 차지한다. 베젤과 옆 가림막은 계산에 포함하지 않는다. 다른 종횡비에서는 표시 영역을 자르지 않고 제한되는 축을 92%로 맞춘다. 기존 `monitorViewportFraction` 필드와 분리해 이전 외곽 기준 값이 새 기준에 재사용되지 않도록 했다.

검증 복사본에서 화면 네 모서리를 뷰포트에 투영해 실제 OS 면적이 80% 이상인지 확인했다. 16:9·4:3·21:9·9:16에서 화면 잘림이 없고, 모니터 클릭 좌표 5지점과 접근 중 입력 차단, Esc 복귀, 기존 OS·메모 저장 검사도 통과했다. 새 실행 이미지는 `Docs/Images/unity-monitor-focus.png`다.

### 2026-10-08 OS 전용 커서

`DesktopCursor`가 UI Toolkit Painter2D로 직접 그리는 전용 커서를 추가했다. 별도 이미지 생성물이나 플랫폼 기본 커서 에셋을 사용하지 않는다. 밝은 화살표/어두운 외곽선/블루 포인트를 기본으로 하고 차콜+세이지 테마에서는 포인트를 세이지로 바꾼다. 버튼은 손 모양, 편집 가능한 입력칸은 I자, 제목 표시줄은 이동, 창의 8방향 가장자리는 해당 크기 조절 모양을 사용한다. 드래그 중에는 창이 캡처한 조작 방향을 유지한다.

커서는 OS의 마지막 장식 레이어에 표시하고 모니터 밖으로 잘라낸다. 커서와 그 레이어는 포인터 선택 대상에서 제외하므로 앱 클릭을 가로채지 않는다. 실제 클릭과 같은 화면→패널 변환을 사용하며 화살표 끝을 클릭 위치에 맞춘다. 컴퓨터 조작이 가능해진 뒤에만 표시하고 접근 중·방 보기·모니터 밖·앱 포커스 상실 시 숨긴다. 컴퓨터 모드에서는 기본 커서를 숨기고 이탈 또는 OS 비활성화 시 이전 표시 상태를 복원한다. 방을 우클릭으로 둘러보는 중에는 기존 카메라의 커서 숨김을 유지한다.

`DesktopCursorVerification`은 별도 Unity 복사본에서 실제 마우스를 움직이지 않는 에디터 전용 입력으로 표시 조건, 클릭 좌표와 화살표 끝, 클릭 통과, 입력칸/버튼/이동/8개 크기 조절 방향, 드래그 캡처, 두 테마, 화면 이탈과 앱 포커스 상실, 방 복귀와 비활성화 정리를 검사한다. 결과는 `Docs/cursor-verification.txt`, 실행 이미지는 `Docs/Images/unity-os-cursor.png`와 `unity-os-cursor-sage.png`다.

### 2026-10-08 저장된 파일 더블클릭과 프로그램 연결 수정

파일 아이콘의 `Button`이 `PointerDownEvent`를 먼저 소비해 후속 더블클릭 콜백이 실행되지 않는 문제를 실제 포인터 이벤트로 재현했다. 바탕화면과 탐색기는 공통 파일 버튼을 사용하고, 완료된 클릭에서 같은 파일 ID·보기·위치의 0.5초 이내 연속 클릭을 판별한다. 운영체제의 클릭 횟수가 전달되지 않는 런타임 패널에서도 동작한다. 한 번 클릭은 선택, 더블클릭·Enter·우클릭 열기는 파일 열기로 연결한다. 현재 가상 파일은 텍스트 문서이므로 메모에서 열고, 폴더는 탐색기로 연다. 최소화된 앱도 다시 표시한다.

기존 저장 형식의 파일 ID와 부모 폴더 ID를 그대로 사용해 동명 파일, 이름 변경, 폴더 이동 후에도 정확한 문서를 연다. 다시 연 메모의 편집은 원본 파일과 저장 폴더에 반영된다. 메모 하단에 현재 전체 경로를 표시하고 긴 경로는 말줄임과 툴팁을 제공한다. 다른 폴더를 열면 이전 탐색기 검색어를 비워 파일이 숨는 현상을 막는다. 기존 사용자 저장 데이터의 형식 변경이나 초기화는 없다.

`DesktopFileActivationVerification`은 아이콘/파일명에 포인터 누름·뗌을 보내고 실제 클릭 위치에 버튼이 노출되는지도 검사한다. 바탕화면·탐색기·목록 보기, 단일/느린/서로 다른 파일 클릭, OS 클릭 횟수 없는 더블클릭, 최소화 복원, 동명 파일 구분, 수정 저장, 이름 변경·이동, OS를 다시 만들어 저장 데이터 읽기 및 다시 열기, 우클릭 열기, Enter, 검색 결과 실행, 잠금 상태 차단을 검증했다. 별도 검증용 저장 폴더에서 전체 OS·방·전용 커서 검사도 통과했다. 결과는 `Docs/file-activation-verification.txt`, 실제 Unity 실행 화면은 `Docs/Images/unity-os-file-opened.png`다.

### 2026-10-08 무료 웹 엔진으로 실제 인터넷 연결

Windows x64용 CEF 152.0.10 / CefSharp 152.0.100을 별도 실행 프로세스로 연결했다. 기존 브라우저 외형 안에 실제 웹페이지 프레임을 표시하고 입력 좌표를 변환한다. 주소/검색, 독립 탭, 웹 페이지 제목, 방문 기록·북마크, 뒤로·앞으로·새로고침과 창 크기 변경을 연결했다. 가상 문서/보관함은 그대로 유지한다. 한글 조합 미리보기와 확정 문자를 따로 보내 중복 삽입을 막으며, 방 보기/잠금/앱 포커스 이탈에서 웹 입력을 해제한다.

대형 브라우저 바이너리는 Git에 넣지 않고 고정된 NuGet 잠금 파일과 재현 가능한 빌드 스크립트를 관리한다. Unity가 CefSharp DLL을 직접 가져오지 않도록 실행 모듈을 Assets 밖에 두고, Windows 게임 빌드 후 별도 BrowserRuntime 폴더로 복사한다. 사용자 PC 브라우저 프로필을 읽지 않으며 웹사이트에 C# 실행이나 가상 파일 접근을 제공하지 않는다. 기본 웹 탐색 범위와 미지원 기능, 설치·빌드·검증 절차는 `Docs/BROWSER.md`를 참조한다.

### 2026-10-08 마우스 기본 시점과 우클릭 확대

방에서는 버튼을 누르지 않고 마우스를 움직여 둘러본다. 우클릭을 누르는 동안 시야각을 기본 58도에서 32도로 부드럽게 줄이며, 놓으면 복귀한다. 카메라 위치와 바라보는 방향은 유지하고 확대 비율에 맞춰 회전 감도를 낮춘다. 컴퓨터 조작 모드에서는 시점이 고정되며 우클릭은 OS 메뉴에 사용한다. 모니터 진입 클릭은 화면 중앙의 시선으로 판정한다.

컴퓨터에서 Esc는 방 복귀, 방에서 Esc는 마우스 해제다. 앱 포커스를 잃어도 확대와 마우스 캡처를 해제한다. 다시 클릭하면 둘러보기만 재개하며 그 클릭으로 컴퓨터까지 열지는 않는다. 캡처를 되찾은 첫 프레임의 마우스 변화는 무시해 시점이 튀는 것을 막는다. 기존 F/Home/H 조작과 메모 보존은 유지한다.

별도 Unity 프로젝트에서 실제 입력 처리 경로를 구동해 버튼 없는 시점 회전, 확대 시작/유지/복귀, 좌석과 시선 유지, OS 입력 차단, Esc/앱 포커스 해제, 재개 클릭, 확대 상태에서 컴퓨터 진입, 우클릭 중 고정된 컴퓨터 시점, 비활성화 정리를 검사했다. 기존 OS·파일 실행·실제 웹·방·커서 검사도 통과했다. 결과는 `free-look-verification.txt`와 `cursor-verification.txt`에 보관한다. 실제 마우스로 느끼는 감도와 확대 속도는 사용자 플레이 검수로 조정할 수 있다.

### 2026-10-08 문 방향·손잡이와 마우스 전용 패드

문짝은 11도 돌아 있었지만 손잡이는 별도 좌표에 있어 떨어져 보였다. `RoomDoor`는 가져온 문짝의 축과 치수를 맞추고 뒤쪽 문설주에 경첩을 만든다. 양면 손잡이의 받침·축·레버는 문짝의 자식이며 받침이 표면과 1mm 겹치도록 붙였다. 문을 화면 중앙으로 보고 클릭하면 0~90도로 부드럽게 열리고 다시 클릭하면 닫힌다. 문이 열려도 앉은 자리의 시야를 막지 않는 방향이다. 기존 출입구의 검은 막을 작은 복도 공간과 따뜻한 조명으로 교체했다. 움직이는 문에는 실시간 그림자와 라이트 프로브를 적용했다.

`DeskMousePad`는 장패드를 숨기고 펄사 eS Saturn Pro Radiant Ruby XL을 참고한 490 × 420 × 4mm 패드를 만든다. 크기는 사용자가 별도로 지정하지 않아 XL로 선택했다. 둥근 모서리와 낮은 봉제 테두리, 붉은 단색 직물과 간략화한 제품명 인쇄를 사용한다. 제조사 사진·CAD·텍스처를 복사하지 않았다. 천 노멀·거칠기는 기존 Poly Haven CC0 지도를 별도 재질에 사용해 바닥 러그에 영향을 주지 않는다. 키보드는 책상 표면, 마우스는 새 패드 윗면에 맞추고 노트와 펜은 패드 오른쪽에 정리했다.

두 구성은 Play 시작 시 기존 가져오기 모델 위에 적용한다. 이미 실행 중이었다면 Stop 후 Play가 필요하다. 방 전체와 조명을 다시 생성하거나 사용자의 작업 씬을 덮어쓰지 않았다. 기존 FBX·Blender 원본은 가져오기 기준으로 남으며 각 제작 스크립트와 자원 출처에 실행 시 변경 사항을 명시했다.

별도 Unity 검증 프로젝트에서 좌석의 중앙 클릭, 점진적인 회전, 전체 회전 중 손잡이 부착, 실제 문 표면과 받침 접촉, 열린 문 너머 복도까지의 시선, 재클릭 닫기를 확인했다. 패드 실제 치수·책상 경계·높이, 마우스 접촉, 키보드 및 노트와의 비겹침, 기존 장패드 비활성화와 러그 보존도 검사했다. 기본 마우스 조작, OS, 파일 실행, 실제 웹, 모니터 시점, 커서 회귀 검사도 모두 통과했다. 기존 Unity 검색 인덱스 초기화 예외는 별도로 발생했으나 게임 검사와 종료는 정상이다. 결과는 `room-props-verification.txt`, 실제 렌더는 `Images/unity-red-mousepad.png`, `unity-door-open.png`, `unity-door-closed.png`다.

### 2026-10-08 냉장고 손글씨 단서와 컴퓨터 전원·비밀번호

냉장고 앞 기존 쪽지에 `1114`를 직접 설계한 펜 선 메시로 적었다. 세 개의 1에 높이 차이를 주고 획을 부드러운 곡선과 둥근 끝으로 이어 필기체 느낌을 냈다. 기울어진 좌석 시점에서 가는 선이 끊겨 보이는 문제는 약 2.7mm 굵기로 보완했다. 잉크는 쪽지 앞에 밀착한 별도 재질이고 종이 경계를 벗어나지 않는다. 추가 폰트나 이미지 자원은 사용하지 않는다.

`PortfolioDesktop.Session`은 꺼짐·부팅·잠금·바탕화면을 관리한다. 매 Play 시작과 OS 재생성 시 꺼진 상태로 시작하며, 로그인 상태는 저장 파일에 기록하지 않는다. `DeskComputerPower`가 책상 아래 본체 전면에 둥근 전원 스위치와 클릭 영역을 만든다. 좌석에서 중앙 시선으로 클릭하면 1.8초의 부팅 후 조건희 계정 로그인 화면이 나온다. 모니터 클릭/F는 접근만 하며 전원을 켜거나 비밀번호를 건너뛰지 않는다. 화면·커서·키보드 입력은 꺼짐/부팅 중 차단한다. 꺼져 있을 때 모니터의 검은 화면, 본체 팬 링·모니터 전원 LED·키보드 물결 LED와 상태 표시등·화면 반사광을 함께 끈다.

잠금 화면은 마스킹된 비밀번호 필드와 제출 버튼을 사용한다. `1114`만 허용하고, 일반 Enter·숫자패드 Enter·화살표 버튼으로 제출한다. 틀리거나 빈 비밀번호는 오류 안내 후 입력을 비운다. 이전의 화면 클릭/빈 Enter 잠금 해제와 무조건 Unlock API를 제거했다. 잠금 중에는 셸과 창을 비활성화하고 OS 단축키를 실행하지 않되 비밀번호의 실제 키 입력은 필드로 전달한다. 메모 입력과 동일하게 비밀번호를 입력할 때 F/H/Home이 카메라를 움직이지 않으며 Esc는 방 시점으로 돌아간다.

다시 잠그면 창을 유지하며 비밀번호를 요구한다. 전원 메뉴의 컴퓨터 끄기는 입력·드래그를 해제하고 파일을 저장한 다음 창과 웹 엔진을 닫고 방으로 돌아간다. 다시 켜면 재인증한다. 기존 파일·테마·방문 기록의 저장 형식을 바꾸지 않았다. 고정 비밀번호는 게임 단서이며 실제 PC 계정과 연결하지 않는다.

별도 Unity 프로젝트의 `ComputerLoginVerification`으로 초기 화면의 검은 픽셀과 전체 표시등 비활성화, 쪽지 경계와 좌석 확대 렌더, 전원 전 앱/비밀번호/접근 차단, 좌석에서 실제 전원 스위치 레이 클릭, 부팅 시간, 잠금 화면, 실제 숫자 키 입력, 빈 입력·오입력·배경 클릭 차단, 마스킹, 정답 제출 버튼 및 숫자패드 Enter, 잠금 중 파일·앱 차단, 창 보존, 전원 종료 시 저장과 재부팅 인증을 확인했다. OS를 디스크에서 다시 만든 뒤에도 꺼진 상태에서 부팅·로그인을 거쳐 파일을 여는 검사로 갱신했다. 기본 시점, 방 소품, OS, 파일 실행, 실제 웹, 모니터 시점, 커서 검사도 모두 통과했다. 기존 Unity 에디터 검색 인덱스 초기화 예외 외 게임 오류는 없었고 검증 프로세스가 정상 종료했다. 결과는 `power-login-verification.txt`, 실행 이미지는 `Images/unity-fridge-password.png`, `unity-fridge-password-seated.png`, `unity-computer-off.png`, `unity-password-login.png`다.
